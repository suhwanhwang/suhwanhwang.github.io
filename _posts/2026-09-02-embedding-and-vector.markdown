트랜스포머 논문("Attention Is All You Need")을 읽다 보면 맨 앞에서 임베딩과 벡터가 나온다.
말은 많이 들었지만 막상 "단어를 벡터로 바꾼다"는 게 무슨 뜻인지, 그 숫자는 누가 정하는지
애매했다. 이 글은 그 물음을 번호 매기기 같은 실패한 시도부터 하나씩 짚어가며 정리한 것이다.
왜 임베딩이라는 방식이 나왔고, 그게 왜 어텐션으로 이어지는지까지 따라가 본다.

## 출발점

신경망은 숫자 계산만 한다. 곱하고 더하는 것뿐이다.
`"앱"`이라는 글자를 그대로 먹일 방법이 없으므로 숫자로 바꿔야 한다.

## 실패한 시도들

### 번호 매기기

```text
앱 → 1,  사용자 → 2,  느리다 → 3,  사과 → 4,  바나나 → 5
```

문제는 번호에 의미가 없다는 점이다. `사과(4)`와 `바나나(5)`가 가까운 건 우연이다.
숫자가 크기와 순서를 가지므로 `앱(1) + 느리다(3) = 사과(4)` 같은
무의미한 연산이 유효하게 취급된다.

### 원핫 인코딩

```text
앱     → [1, 0, 0, 0, 0]
사과   → [0, 0, 0, 1, 0]
바나나 → [0, 0, 0, 0, 1]
```

크기 문제는 해결된다. 하지만 **모든 단어가 서로 똑같이 멀다.**
`사과`와 `바나나`가 `사과`와 `사용자`만큼 멀다. 관계 정보가 없다.
그리고 어휘가 10만 개면 배열 하나가 10만 칸이고 그중 99,999개가 0이다.

## 임베딩

발상을 전환한다. 단어를 **여러 성질의 조합**으로 표현한다.

```text
축:        [먹을수있음, 생물, 기술, 사람]
사과    → [  0.9,      0.7,  0.0,  0.0]
바나나  → [  0.9,      0.8,  0.0,  0.0]
앱      → [ -0.8,     -0.9,  0.9,  0.0]
사용자  → [ -0.9,      0.9,  0.3,  0.9]
```

`사과`와 `바나나`의 좌표가 거의 같다. 비슷한 성질을 가졌기 때문이다.

### 벡터 = 공간 속의 한 점

"벡터"는 **좌표**라고 생각하면 정확하다.
2차원이면 지도 위의 점 `(3, 5)`다. 임베딩은 축이 512개인 공간의 점일 뿐이다.
머릿속에 그려질 필요는 없다. 계산은 차원 수와 무관하게 동일하다.

**핵심 성질:**

> 의미가 비슷한 단어는 공간에서 가까이 있다.
> 의미의 유사도가 공간상의 거리로 바뀐다.

### 그 숫자는 누가 정하나

**아무도 정하지 않는다.** 처음엔 완전히 무작위다.

```text
앱 → [0.31, -0.72, 0.05, ...]   ← 그냥 난수
```

엄청난 양의 문장을 읽으며 학습으로 조금씩 수정된다. 원리는 한 줄이다.

> 비슷한 자리에 등장하는 단어들은 비슷한 좌표로 모인다.

`사과`와 `바나나`는 "~를 먹었다", "~가 익었다" 같은 비슷한 문맥에 나오므로
두 벡터가 가까워진다. `앱`은 다른 문맥에 나오므로 멀어진다.

**그래서 축에는 이름이 없다.** 학습된 모델의 137번째 축이 무슨 의미인지
아무도 모른다. 위의 축 이름은 순전히 이해를 돕기 위한 장치다.

### king - man + woman ≈ queen

학습 과정에서 "성별"에 해당하는 **방향**이 공간에 자연스럽게 생긴다.
아무도 그런 축을 만들라고 지시하지 않았는데도 말이다.
의미의 **관계**가 공간의 **방향**으로 표현된 것이다. 임베딩이 강력한 이유다.

## 논문과의 연결

논문 3.4절에서는 학습된 임베딩으로 토큰을 `d_model` 차원 벡터로 변환한다.

- `d_model = 512` → **축이 512개**
- "학습된(learned)" → 사람이 정한 게 아니라 훈련으로 얻어졌다는 뜻
- Figure 1 맨 아래 `Input Embedding` 박스가 이 단계

## 개발자 관점

```kotlin
// 토큰 ID → 512개짜리 실수 배열
val embedding: Array<FloatArray> = Array(50000) { FloatArray(512) }
fun lookup(tokenId: Int): FloatArray = embedding[tokenId]
```

5만 × 512 테이블이다. 조회는 단순 인덱싱이고 특별할 게 없다.
특별한 건 그 2560만 개의 숫자가 **전부 학습 대상**이라는 점이다.

## 한계 → 어텐션으로 이어짐

```text
"강에서 배를 탔다"
"과일 중에 배가 제일 맛있다"
"운동하다 배가 아프다"
```

세 문장의 `배`가 전부 같은 벡터를 받는다. 테이블 조회니까.
문맥이 개입할 여지가 없다.

**이 한계를 푸는 것이 어텐션이다.**

| 개념 | 역할 |
|---|---|
| 임베딩 | 문맥 없는 사전적 의미. 출발점 |
| 어텐션 | 그 벡터를 문맥에 맞게 갱신 |
| 트랜스포머 | 이 갱신을 여러 층에 걸쳐 반복 |

## 요약

| 개념 | 한 줄 |
|---|---|
| 벡터 | 여러 숫자를 묶은 것. 공간 속의 좌표 |
| 차원 | 축의 개수. 논문에서는 512 |
| 임베딩 | 단어를 벡터로 바꾼 것. 학습으로 얻어짐 |
| 핵심 성질 | 의미가 비슷하면 공간에서 가깝다 |
| 한계 | 문맥 반영 불가 → 어텐션이 해결 |
